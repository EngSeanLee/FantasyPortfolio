# EngSean Lee — AI Portfolio Master Brief

## Document Purpose

This document is the source of truth for the creative direction, product strategy, information architecture, interaction model, motion language, content structure, and visual intent of EngSean Lee’s professional AI portfolio.

The site should not feel like a fantasy fan site, a résumé with fantasy decoration, or a small indie game pretending to be a portfolio.

It should feel like a premium professional portfolio designed by a team that understands:

- enterprise systems
- AI solutions architecture
- process strategy
- executive communication
- modern web interaction
- AAA fantasy game art direction
- environmental storytelling
- polished UX

The central idea is:

> **A professional AI architecture portfolio presented as a journey through an optimistic fantasy world.**

The fantasy exists primarily in the visual language, environmental design, spatial composition, motion, and interaction behavior. The written language remains credible, clear, and corporate.

# 4. Design Principles

## 4.1 Professional First

A hiring manager should be able to understand the portfolio even if they have never played a Final Fantasy game.

Fantasy influence should elevate the experience, not become a prerequisite for understanding it.

## 4.2 Systems Before Solutions

The site should repeatedly reinforce the idea that successful technology and AI work begins with the operating problem, workflow, constraints, information structure, and governance.

Suggested philosophy line:

> **Technology creates value when it reduces friction, improves decision-making, or fundamentally changes how work gets done.**

Supporting idea:

> **My approach to AI begins with the operating problem—not the tool.**

## 4.3 Interactivity Must Reveal Information

Every interactive element should serve at least one purpose:

- reveal useful information
- demonstrate relationships
- help navigate
- communicate depth
- improve understanding
- create emotional atmosphere

Do not add interaction merely to prove that something can move.

## 4.4 Visual Boldness, Behavioral Restraint

Target visual intensity: **7/10**

Target interaction intensity: **5–5.5/10**

The site may look ambitious, cinematic, and unusual while still behaving predictably.

## 4.5 AI Is Part of the Method, Not the Entire Identity

The portfolio should show that AI extends EngSean’s existing strengths in process, governance, project discipline, enterprise planning, and problem solving.

It should never read as:

> “I discovered generative AI and now I am an AI expert.”

Instead:

> “I have spent my career solving operational problems. AI gave me a powerful new layer of tools for doing that.”

# 6. Environmental Motion

The background must not be static.

The environment should feel alive at all times, but never distract from reading.

## 6.1 Constant Ambient Motion

Use subtle, slow movement:

- clouds drifting
- tall grass and flowers moving in wind
- distant birds coasting
- foreground grass responding differently than midground grass
- very light atmospheric particles
- slight water shimmer where appropriate
- extremely subtle light variation

## 6.2 Occasional Motion

Examples:

- small flock of birds crossing the sky
- isolated petals or seed particles moving through foreground
- distant cloud shadow passing over the meadow
- soft light shimmer across the landscape

These should be infrequent enough to feel natural.

## 6.3 Scroll-Based Motion

Scrolling may create:

- slight camera push toward the landscape
- subtle parallax between foreground, meadow, ruins, mountains, and sky
- increasing prominence of the distant landmark
- gentle depth transitions between major sections

Do not make the user feel like they are controlling a character.

## 6.4 Motion Intensity

Recommended scale:

- ambient background movement: 3/10
- hero movement: 4/10
- hover interactions: 5/10
- section transitions: 6/10
- case study transitions: 6/10

## 6.5 Motion Rules

Avoid:

- bouncing
- elastic animation
- excessive rotation
- rapid zooms
- constant camera drift while text is being read
- aggressive particle effects
- looping animation that becomes obvious after several seconds

Preferred motion:

- fade
- line draw
- slow parallax
- focus shift
- slight scale from 0.98 to 1.00
- restrained glow
- reveal
- smooth mask transitions
- natural environmental movement

Suggested timings:

- micro interaction: 150–250ms
- hover reveal: 200–350ms
- section transition: 500–800ms
- cinematic transition: 1.5–3 seconds

# 13. Project Case Study Structure

Every featured project follows the same executive-friendly structure.

## Section 01 — Problem

Explain the operating problem clearly.

Use a concise, high-impact headline first.

Example pattern:

> **The problem was not X. It was Y.**

Then supporting detail.

## Section 02 — Project Overview

Explain what was designed or built.

Focus on:

- intended operating change
- key solution characteristics
- governance or process considerations
- implementation approach

## Section 03 — Architecture

Show a visual architecture diagram.

Architecture diagrams should feel like designed product visuals, not copied Visio screenshots.

Visual style:

- champagne line work
- sage active nodes
- ivory background
- thin connectors
- subtle animation
- clean sans-serif labels

## Section 04 — AI & Technology Layer

Use this label rather than “AI Model” so projects that are not model-centric still fit.

Possible fields:

- platform
- model / AI environment
- agent architecture
- prompt / instruction strategy
- data layer
- integrations
- controls / guardrails
- persistence
- workflow orchestration

Only show fields that actually apply.

## Section 05 — Business Impact

Prefer measurable impact where supported.

Do not invent metrics.

If metrics are unavailable, use outcome categories such as:

- reduced manual effort
- increased consistency
- stronger governance
- improved visibility
- improved scalability
- reduced rework
- faster execution
- more reliable documentation

Large metric-style callouts are encouraged when supported.

Example:

**HOURS → MINUTES**

## Section 06 — Lessons Learned

This section is important.

Show professional reflection, not false perfection.

Examples:

- AI produces stronger enterprise value when ambiguity is intentionally reduced.
- Governance works best when embedded in the workflow.
- Structured outputs are often more useful than unrestricted generation.
- Persistent context can be more valuable than one-off AI responses.

## Section 07 — Related Systems

Allow continued exploration.

Show previous / next related projects.

## 14.1 Enterprise Estimate Intake System

### Problem

A manual spreadsheet-driven estimate process created risks around duplicate submissions, conflicting information, poor status visibility, and weak auditability across multiple internal teams.

### Project Overview

Designed a low-code intake and tracking system to standardize estimate collection, enforce workflow states, prevent duplication, surface deadlines, and create a controlled revision process.

### Architecture

Key elements:

- low-code application layer
- structured list-based data layer
- duplicate-prevention logic
- draft → submit → lock workflow
- visual due-date flags
- required change-reason capture for revisions

### Business Impact

Supported outcomes:

- eliminated duplicate/conflicting estimate submissions
- created an audit trail
- improved at-a-glance status visibility
- created a more governed workflow

### Portfolio Positioning

This is an important example of **process before AI**.

It demonstrates that the right solution is not always an AI model. Strong operational design creates the structured foundation that future AI capability may depend on.

## 14.2 Process Build Coach Agent

### Problem

A self-directed builder without prior platform expertise needed a way to avoid architectural mistakes, governance failures, duplicate-entry risks, lock bypasses, and broken audit behavior while building a scalable workflow.

### Project Overview

Created a custom AI coaching agent that acted as a structured architecture reviewer rather than a documentation dump.

### Architecture

Key elements:

- custom GPT-based agent
- embedded architecture rulebook
- step-by-step “teach as you build” guidance
- delegation-safety checks
- governance guardrails
- state-machine awareness
- protections against duplicate creation
- protections against lock bypass
- protections against audit trail failure

### Business Impact

Supported outcomes:

- enabled a single builder to create a more scalable system
- caught architectural mistakes before implementation
- strengthened governance and workflow integrity
- reduced dependence on prior platform expertise

### Lessons Direction

- AI is more valuable when constrained by explicit operational rules.
- Coaching and architecture-review agents may create more value than simple content generation.
- Governance-aware AI is more credible in enterprise environments.

# 25. Asset Strategy

The environment may be constructed from multiple layers rather than one static image.

Suggested layers:

1. sky / cloud layer
2. distant mountain layer
3. landmark / observatory layer
4. midground ruins and water
5. meadow layer
6. foreground grass / flower layer
7. birds
8. atmospheric particles
9. UI layer

This allows:

- parallax
- subtle motion
- depth
- responsive cropping
- more natural environmental movement

Do not attempt to animate a single flat image with excessive distortion.

# 29. Creative Guardrails

Before adding any new visual or interaction idea, ask:

1. Does this improve the visitor’s understanding?
2. Does it reinforce the professional story?
3. Does it support the fantasy atmosphere without becoming cosplay?
4. Would a senior hiring manager still take the page seriously?
5. Does it work without sound?
6. Does it work with reduced motion?
7. Does it preserve performance?
8. Is the content still the hero?

If the answer to several of these is no, remove the idea.
